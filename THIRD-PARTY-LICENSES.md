# Third-party licences

Tyche is licensed **AGPL-3.0-or-later** (see [LICENSE](LICENSE)), and under no
other terms. That covers the code in this repository. It does not cover the
code Tyche is built on, and a downloadable release is mostly that other code:
a Linux build of the source *without* PyTorch already contains 95 native
binaries, and not one of them was written for Tyche. Tyche's own code travels
through them as Python bytecode.

This file is the inventory of what those binaries are and what licenses them.

## How this was produced

The authoritative inventory is **not this file**. It is the one inside the
archive you downloaded, at `licenses/THIRD-PARTY-LICENSES-<platform>.md`,
generated by [`tools/licence_inventory.py`](tools/licence_inventory.py) on the
runner that built that archive — the only machine whose answer is your
download's own. PyInstaller collects whatever the build machine's linker
resolved, so the contents change when the runner image changes, not when
somebody edits this repository.

Tyche cannot be built faithfully outside CI, which is why it is done that way:
the release installs a CPU-only PyTorch from PyTorch's own package index, and
a build made without that index gets the CUDA wheel and gigabytes of NVIDIA
proprietary libraries that no release has ever shipped. A hand-maintained list
would be stale within one CI image bump and nobody would notice.

> **This file describes the source, not a specific build.** The tables below
> are the direct dependencies and the constraints that follow from them, which
> are properties of `requirements.txt`. The per-binary table is refreshed by
> lifting the generated copy out of a release archive; the archives for 0.8.0
> are the first to carry one, since every archive up to 0.3.3 shipped no
> licence file at all.

Every entry in the generated inventory traces to a machine-readable source:

- **Python packages** — the top-level package a binary sits under names its own
  distribution, and that distribution's installed metadata states its licence.
- **Libraries collected from the Linux build machine** — the owning package
  from `dpkg-query`, and that package's `debian/copyright`.
- **Libraries the platform supplies** (the Windows CRT, the OpenSSL that ships
  inside python.org's builds) — identified by name, since no package manager
  owns them.

Two traps in that lookup are worth stating, because both produced wrong answers
before they were caught, and both are handled in the script rather than papered
over:

A `debian/copyright` file enumerates every licence appearing anywhere in the
*source* package, test fixtures and build scripts included. Reporting that
union is alarmist nonsense. What governs a shipped shared library is the
licence of that library's own sources — the stanza whose `Files:` pattern
covers them.

And even the `Files: *` stanza is wrong when one source package builds several
libraries under different terms. util-linux's default stanza says GPL-2+, while
`libuuid`, which these builds do ship, is BSD-3-clause in its own stanza.
Taking the default would have published a wrong answer that looked
authoritative. Those cases are in the script's `REVIEWED` table, each with the
stanza that was read.

Anything the script cannot resolve is reported as **unresolved** rather than
guessed at. A gap you can see is worth more than a plausible-looking entry that
is wrong.

## What Tyche depends on directly

Four packages, declared in [`requirements.txt`](requirements.txt), with the
licence each one's own metadata states. The version column is what was
installed when this was last checked; a release carries whatever
`requirements.txt` resolved to on the day it was built, and the copy of the
inventory inside that archive names those versions.

| Package | Version checked | Licence (from its metadata) | What Tyche uses it for |
|---|---|---|---|
| CustomTkinter | 6.0.0 | `CC0-1.0` | the interface |
| NumPy | 2.5.3 | `BSD-3-Clause AND 0BSD AND MIT AND Zlib AND CC0-1.0` | every feature matrix and every statistic |
| requests | 2.34.2 | `Apache-2.0` | fetching the draw archive, and the certificate bundle behind it |
| timesfm[torch] | ≥3.0 | `Apache-2.0` | the forecast model's own code |

`timesfm[torch]` pulls in **PyTorch** (`BSD-3-Clause`, with Apache-2.0, BSL-1.0
and MIT parts) and **huggingface-hub** (`Apache-2.0`), which is what fetches the
checkpoint. Those two decide the size of the archive. Arriving with them rather
than being asked for: `certifi` (MPL-2.0), `charset-normalizer` (MIT), `idna`
(BSD-3-Clause), `urllib3` (MIT), `darkdetect` (BSD-3-Clause), `packaging`
(Apache-2.0), `filelock`, `fsspec`, `jinja2`, `networkx`, `sympy`.

**None of these is copyleft in a way that reaches Tyche's own code.** MPL-2.0,
which `certifi` carries, is file-level weak copyleft: it governs `certifi`'s own
files and nothing else. Nothing here requires Tyche to be AGPL — that is a
choice, not an obligation inherited from a dependency.

Deliberately absent, and worth not reintroducing: **pandas**, because the
archive is a few thousand rows read once into a list of frozen dataclasses;
**SciPy**, because `core/stats_tests.py` implements the four distribution
functions the analysis needs in about a hundred lines, and every number in the
validation report is a claim about whether a prediction beat chance that a
reader must be able to check without leaving the repository;
**beautifulsoup4**, because `core/sources/html_table.py` works on rows, cells
and positions rather than on CSS classes.

### The model weights are the one real restriction

**Model weights are licensed separately from model code, and here they are not
free software.** The `timesfm` *package* is Apache-2.0. The *weights* are not.

`google/timesfm-3.0-pytorch`, which Tyche loads by default, is published under
**`timesfm-non-commercial-license-v1.0`**: non-commercial, non-production use
only. Checked against the model cards on 6 September 2026 by the
`checkpoint-licence` job in [`.github/workflows/ci.yml`](.github/workflows/ci.yml),
which anyone can re-run:

| Checkpoint | Declared licence |
|---|---|
| `google/timesfm-3.0-pytorch` | `other` → `timesfm-non-commercial-license-v1.0` |
| `google/timesfm-2.5-200m-pytorch` | `apache-2.0` |
| `google/timesfm-1.0-200m-pytorch` | `apache-2.0` |

None of the three is gated: the weights download without anyone accepting
anything, which is exactly how a restriction like this goes unnoticed.

**They are not in this inventory because they are not in the bundle.** Tyche
downloads them from Hugging Face the first time a forecast runs, onto the
machine running it — so nothing on the releases page contains them, and nothing
a Tyche redistributor hands over includes them. The person who runs the program
is the party that licence binds.

**What it means for you.** The AGPL lets you use Tyche for any purpose,
including commercially. That permission is Tyche's to give and it is given. It
does not extend to the TimesFM 3.0 weights, which are not Tyche's to license:
running the `timesfm` method commercially would need the 2.5 checkpoint, which
is Apache-2.0 and which the checkpoint setting already accepts — though
`core/forecaster.py` is written against the 3.0 API and would need work to
drive it.

Every other method in the program — `frequenza`, `ritardo`, `casuale` — and the
whole archive, statistics, independence-testing and validation machinery runs
without downloading any weights at all.

## The components that actually constrain redistribution

Most of what a bundle contains is BSD, MIT or Apache-2.0 and asks only that the
notice travels with the binary, which is what `licenses/` inside the archive is
for. Three things ask for more, and all three are in every Linux build:

| Component | Licence | What it actually requires |
|---|---|---|
| `libgcc_s`, `libstdc++`, `libobjc` | `GPL-3.0-or-later WITH GCC-exception-3.1` | Nothing, for a binary compiled with GCC: the runtime exception exists precisely so a program linking them is not made GPL. |
| Tcl and Tk | `TCL` (BSD-style) | Reproduce the notice and the disclaimer. Both texts travel; they name different copyright holders and cite different DFARs clauses, so one does not stand in for the other. |
| any LGPL library the Linux runner collects | `LGPL-2.1` / `LGPL-3.0` | A copy of the licence with the object code, and the recipient's ability to relink. Tyche is a **folder** build, so every such library is an ordinary file in it: replacing one with a modified build of the same library is overwriting a file. |

The draw data is a fourth thing, and not a licence question in the same sense.
Historical results are facts, not creative works, and facts are not
copyrightable. The *compilations* Tyche downloads are another matter: each
source publishes its archive under its own terms, and those terms govern
redistributing a copy of that archive. They do not reach the numbers
themselves. Tyche ships no archive — `data/` is git-ignored and every file in
it was fetched by whoever ran the program.

## What was deliberately removed

The standard library's optional `readline` extension links **libreadline**,
which is GPL-3.0-or-later with no linking exception — the one licence in reach
that would reach Tyche's own code. Tyche is a windowed program that never reads
a line from an interactive prompt, so it is excluded in
[`Tyche.spec`](Tyche.spec), together with `rlcompleter`, which imports
`readline` and exists for nothing else. Argus and Orion exclude the same pair.
`tests/test_packaging.py` fails if either comes back.

The test frameworks are excluded for a different reason: PyInstaller otherwise
follows an import in a dependency and drags `pytest` into a shipped binary.

## Licence texts travel with the build

`licenses/` inside every archive holds the terms of everything in it — Tyche's
own AGPL as `Tyche-LICENSE.txt`, CPython's and Tcl/Tk's from
[`licenses/`](licenses) in this repository, each wheel's own copy read out of
its installed metadata, and on Linux the build machine's `debian/copyright`
record for every system library PyInstaller collected.

[`tools/collect_licences.py`](tools/collect_licences.py) assembles it, and what
it collects is read out of PyInstaller's own record of what it collected rather
than from a list kept by hand. A hand-kept list is right on the day it is
written and wrong the first time a dependency grows a dependency of its own —
the one failure mode where being wrong looks exactly like being right.

A distribution that puts a binary in the bundle and no notice in `licenses/` is
reported by the release job, because the inventory is run with `--licences`
pointed at the tree that is about to be packaged.

## Full inventory

The per-binary table lives in the archive, not here: `licenses/`
`THIRD-PARTY-LICENSES-windows-x64.md`, `-macos-arm64.md` or `-linux-x64.md`
depending on which one you downloaded. Each row names the evidence it rests on
so it can be re-checked, and rows the script could not attribute are printed as
**unresolved** rather than guessed at. These are statements about what the
declared metadata and the build machine's own records say, current as at the
version of this document, and are **not a legal opinion**.

For the shape of it: a Linux build of this source made without PyTorch contains
95 native binaries — 25 CPython extension modules, 31 libraries from the build
machine, 39 from wheels. A release adds PyTorch's, which is most of the 160 MB.

## Build-time tools

**PyInstaller** (`GPL-2.0-or-later WITH Bootloader-exception`) produces the
executable. The exception is what makes that possible: it permits the
bootloader — which *is* shipped, as the first thing the program runs — to be
combined with a program under any licence. Its `COPYING.txt` therefore travels
in `licenses/` like any shipped component's.

Everything else in [`requirements-dev.txt`](requirements-dev.txt) — pytest,
ruff, PyYAML — runs on a developer's machine and on CI and is in no archive, so
its terms are not reproduced in one.

## Known gaps

**The tables cover native binaries only.** Python code frozen into the bundle
as bytecode is not in them, and that is where a copyleft licence is most likely
to hide: a pure-Python package has no `.so` for the inventory to find. What
covers that is the direct-dependency table above, read from installed metadata,
plus the fact that `licenses/` collects a notice per *distribution* rather than
per binary. A reader who takes a clean per-binary table as proof that nothing
copyleft is in the bundle would be drawing a conclusion it does not support.

**The versions in this file are a snapshot.** They are what was installed when
it was last checked, not what a given release built against. The copy of the
inventory inside your archive is the one that names your versions.

**The weights are outside all of it,** by design, and the section above is the
only place their terms are stated. Nothing in `licenses/` covers them, because
nothing in the archive is them.

## Reproducing this

```
python - <<'PY'
import importlib.metadata as m
for pkg in ("customtkinter", "numpy", "requests", "timesfm", "torch"):
    md = m.metadata(pkg)
    print(pkg, m.version(pkg), md.get("License-Expression") or md.get("License"))
PY
```

For a bundle, build it and then run the two scripts the release job runs:

```
python build.py
python tools/collect_licences.py build/licenses
python tools/licence_inventory.py --bundle linux=build/Tyche \
    --licences build/licenses --markdown inventory.md
```

Exit code 2 means the report was written and some rows in it need a human.

And for the checkpoints, dispatch the `CI` workflow and read the
`checkpoint-licence` job.
